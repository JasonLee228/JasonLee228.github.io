> 💡 회원과 팀이 있다.

### 양방향 연관관계

- 팀 객체를 통해 맴버를 조회/관리할 수 있을까?

#### 연관관계의 주인과 mappedBy

![image](/assets/images/54692f7c473c403a9da1a65ce156accf.png)

1. **객체와 테이블이 연관관계를 맺는 차이**

- 객체 연관관계 → 2개
    - 회원 → 팀 연관관계 1개(단방향)

    - 팀 → 회원 연관관계 1개(단방향)

- 테이블 연관관계 → 1개
    - 회원 ↔ 팀 연관관계 1개(양방향)

1. 객체의 양방향 연관관계

> 객체의 양방향 관계는 단방향 두개로 양방향을 흉내내는 것.  
> 참조 관계로 나타내는 객체에서는 양방향 참조를 위해서는   
> 단방향 연관관계가 두 개가 있어야 한다.

1. 테이블의 양방향 연관관계

> 테이블은 외래 키 하나로 두 테이블의 연관관계를 관리할 수 있다.  
> → 조인을 통해 양쪽으로 조회 가능

---

#### 연관관계의 주인(Owner)

- 외래 키 관리를 member에서 할 지, team 에서 할 지의 딜레마를 해결하기 위해 등장

- member 의 fk 를 [member.team](http://member.team) 을 통해 관리할지, team.members 를 통해 관리할지 정해야 한다.

1. 양방향 매핑에서의 rule(규칙)

- 객체의 두 관계중 하나를 연관관계의 주인으로 지정

- **연관관계의 주인만이 외래 키를 관리(등록 / 수정)**

- **주인이 아닌 쪽은 read 권한만 가진다.**

- 주인은 mappedBy 속성 사용 X

- 주인이 아니면 mappedBy 속성으로 주인 지정

{% raw %}
```java
@Entity
public class Member {

...
    @ManyToOne
    // 조인의 대상이 되는 컬럼(fk)
    @JoinColumn(name = "TEAM_ID")
    private Team team;
...

@Entity
public class Team {
...
    @OneToMany(mappedBy = "team") // team 이라는 필드에 의해 관리된다(주인 지정)
    private List<Member> members = new ArrayList<>();
...
```
{% endraw %}

1. 누구를 주인으로 지정하는가?

- **외래 키가 있는 곳**을 주인으로 정해라. N:1 관계에서 N 쪽이 주인이 된다(테이블 구조에서 외래키는 N 쪽에 존재한다)

- **이번 예제에서는 **[**member.team**](http://member.team)** 이 주인이 되는 것!**

![image](/assets/images/8c40ea2206054211996c3c61e553fd84.png)

1. 값 입력 주의

- 무조건 주인쪽에 값을 입력하기

- read 권한만 가진, 주인이 아닌 쪽에서 아래와 같이 입력해봐야 변경되지 않는다.

{% raw %}
```java
// 잘못된 코드(주인이 아닌 쪽에서 입력 시도)
Team team = new Team();
team.setName("TeamA");
em.persist(team);

Member member = new Member();
member.setName("member1");
team.getMembers().add(member);
em.persist(member);


// 정상적인 코드
Team team = new Team();
team.setName("TeamA");
em.persist(team);

Member member = new Member();
member.setName("member1");
member.setTeam(team); // *******
em.persist(member);
```
{% endraw %}

#### 예제) Member 를 통해 Team을 조회하고, Team의 Member 리스트를 조회해보자.

{% raw %}
```java
Team team = new Team();
team.setName("TeamA");
em.persist(team);

Member member = new Member();
member.setName("member1");
member.setTeam(team);
em.persist(member);

em.flush();
em.clear();

Team findTeam = em.find(Team.class, team.getId());
// 이 때 연관관계가 있다는걸 JPA 가 알기 때문에 select 쿼리 날림.
List<Member> members = findTeam.getMembers();

for (Member m : members) {
    System.out.println("m = " + m.getName());
}
```
{% endraw %}

#### ⚠️ 주의사항

- member, team 둘 다에 서로 값을 세팅해줘야 하는 때가 있다.
    - 그냥 해주는게 좋다.

> 💡 위처럼 코드를 작성하는 경우에는 아무런 문제가 없다.
> 하지만 em.flush(), em.clear() 하는 부분이 없다면 문제가 발생.
> 1차 캐시에 팀이 생성되기만 한 채로 있기 때문에 em.find 하게 될 시에 1차 캐시에서 findTeam 값을 가져오게 될 거고, 연관된 맴버의 값이 없기 때문에 별도의 select 쿼리를 날리지 않게 됨. → members 값이 없음

- 그렇다면 한쪽 설정할 때 양 쪽 다 설정할 수 있게 하자!

{% raw %}
```java
// member.setTeam 할 때 team 쪽에도 member 를 설정하도록 편의 메소드 작성
public void setTeam(Team team) {
    this.team = team;
    team.getMembers().add(this);
}
```
{% endraw %}

#### 정리

- **사실 단방향 매핑으로 테이블 간의 연관 관계 매핑은 완료된 것(FK 설정됨)**

- 양방향 매핑은 반대 방향으로의 조회가 필요할 경우 추가하는 것
    - 객체 그래프 탐색 기능이 추가된 것 뿐

- 단방향 매핑을 잘 하고, 양방향은 테이블에 영향을 주지 않기 때문에 필요할 때 추가해도 된다.

> _본인도 실제 실무에서 양방향을 잘 사용하지 않는 듯 하다._

- **연관관계의 주인**은 비즈니스 로직을 기준으로 정하는 것이 아니다.
    - **외래 키의 위치를 기준으로 정해야 함**

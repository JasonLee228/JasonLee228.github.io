[2751번: 수 정렬하기 2](https://www.acmicpc.net/problem/2751)

### 문제

> 💡 N개의 수가 주어졌을 때, 이를 오름차순으로 정렬하는 프로그램을 작성하시오.

---

### 입력

> 💡 첫째 줄에 수의 개수 N(1 ≤ N ≤ 1,000,000)이 주어진다. 둘째 줄부터 N개의 줄에는 숫자가 주어진다. 이 수는 절댓값이 1,000,000보다 작거나 같은 정수이다. 수는 중복되지 않는다.

---

### 출력

> 💡 첫째 줄부터 N개의 줄에 오름차순으로 정렬한 결과를 한 줄에 하나씩 출력한다.

### 코드 설명 

이전의 정렬 문제들과는 다르게, 이번에는 O(nlogn)의 시간복잡도 제한이 걸려 있는 문제였다.  
필자는 동빈나의 알고리즘 강의를 보며 공부하고 있었기 때문에, 퀵 정렬로 문제 해결이 가능하다고 듣고 퀵 정렬 알고리즘을 사용하여 풀었으나,,,

![image](/assets/images/15b7795ba67543e3ae0015286fafc4ad.png)

이런 식으로 시간 초과가 뜨게 된다. 혹시나 하여 코드가 잘못된 부분이 있나,,하고 수정도 해보고 찾아보기도 했지만, 결국 알아낸 사실은 백준에서 컴파일 예제로 퀵 정렬의 최악 시간인 O(n^2)를 뜨게 할 수 있는 예를 넣어뒀다는 것. (결국 삽질이었다,;;)

이후 퀵 정렬을 단순히 구현한 것으로 안 되어 Arrays클래스 내의 Sort()메소드를 사용했으나, 최적화된 퀵 정렬 알고리즘을 사용한다고 알고 있었던 메소드임에도 불구하고 시간 초과.

다음으로 시도해 본 방법이 바로 Collections클래스의 Sort()메소드이다. Arrays클래스의 메소드와 다른 점은, Collections.sort는 합병 정렬+삽입 정렬이라는 것. 때문에 Arrays.sort에 비해서 속도가 빠르다. 

또한, Collections클래스를 활용하기 위해서는 단순 배열이 아닌, List 계열(ArrayList, LinkedList 등..)의 자료구조를 사용하여 정렬해야한다. 따라서 필자는 ArrayList를 사용하였다.

{% raw %}
```java
import java.util.Scanner;
import java.util.ArrayList;
import java.util.Collections;
 
 
public class Main {	
	public static void main(String[] args) {
    
		Scanner in = new Scanner(System.in);
		StringBuilder sb = new StringBuilder();
		
		int N = in.nextInt();
		
		// list 계열 중 하나를 쓰면 된다.
		ArrayList<Integer> list = new ArrayList<>();
		
		for(int i = 0; i < N; i++) {
			list.add(in.nextInt());
		}
		
		Collections.sort(list);
		
		for(int i : list) {
			System.out.println(list.get(i));
		}
		
	}
}
```
{% endraw %}

> 💡 하지만 문제는 역시나 있던 법. 시간초과에서 벗어나지 못한다.
> 문제에서의 시간 범위를 정렬과 출력까지 모두 고려하여 정해놓은 듯 했다.
> 기본적으로 System.out.println을 사용할 때 시간과 메모리를 꽤 많이 잡아먹는다고 한다.
>
> 해서 알아보니, 출력 시간을 줄이기 위해서는 '버퍼'를 사용해 줄인다 한다.
> 단순히 for문을 통해서 출력하게 된다면, 매 번 새로운 버퍼를 생성하게 되고, 여기서 이루어지는 시간과 메모리적 부하가 꽤 크다는 것.
>
> 해서 문제를 풀다 보니 String, Stringbuffer, Stringbuilder까지 공부하게 된 문제였다.
> 파훼법은 Stringbuilder을 이용해 배열을 모두 합쳐준 뒤, 한번에 버퍼를 출력해 주는 것. 시간이 비약적으로 빨라졌다.

### 마치며

> 💡 알고리즘을 공부하며, 문제를 풀어가다 보니 메모리적 효율성과 시간 관리의 중요성을 깨달아 가는 것도 있는 것 같다. 한정된 자원이 주어졌을 경우 최적화를 통해 더 적은 자원, 더 적은 시간을 할애할 수 있다는 것에 매력을 느끼고 있고, 이번 문제를 통해서 scanner뿐 아니라 buffer을 사용하는 입출력 방법에 대해서 알고, 공부할 수 있었던 좋은 문제였다고 생각한다.

### 6 - 컴포넌트 스캔

> ❓ `@Component` 어노테이션이 붙은 클래스를 스캔해서 스프링 빈으로 등록한다.

{% raw %}
```java
@Configuration
@ComponentScan(
        excludeFilters = @ComponentScan.Filter(type = FilterType.ANNOTATION, classes = Configuration.class)
)
public class AutoAppConfig {
    // @Bean 으로 뭔가 설정한게 없다!
}
```
{% endraw %}

- 컴포넌트 스캔 및 의존성 자동 주입이 잘 이루어졌는지 알기 위한 테스트

{% raw %}
```java
@Test
    void basicScan() {

        // AutoAppConfig 에는 별도로 설정정보를 만들지 않았지만 컴포넌트 스캔을 통해 빈 등록 및 주입이 잘 이루어짐을 알 수 있다
        AnnotationConfigApplicationContext ac = new AnnotationConfigApplicationContext(AutoAppConfig.class);
        MemberService memberService = ac.getBean(MemberService.class);

        assertThat(memberService).isInstanceOf(MemberService.class);

    }
```
{% endraw %}

> ❓ **ClassPathBeanDefinitionScanner 에서 컴포넌트 스캔(빈 등록 대상) 을 미리 식별한 것을 볼 수 있고,
> DefaultListableBeanFactory 에서 자동 의존성 주입, autowired를 해 주는 것을 볼 수 있다.**

- 컴포넌트 스캔이 어떻게 동작하는가?

> 📌 컴포넌트 스캔의 동작 방식
>
> - `@Component` 가 붙은 클래스 전부를 빈으로 등록한다.
>     - 제외 지정 가능!
>
> - 등록되는 빈의 기본 이름은 클래스명을 사용한다.
>     - 맨 앞글자는 소문자를 사용하여 빈 이름을 등록
>
>     - 직접 이름을 지정하여 등록하고 싶다면 `@Component("등록하고 싶은 빈 이름")` 

> ❓ 자동 의존성 주입의 동작 방식
>
> - `@Autowired`가 붙은 생성자 또는 주입을 원하는 부분에서 스프링이 자동으로 빈을 찾아서 등록해준다.
>
> - 조회는 빈의 타입(이름)이 같은 걸 찾아서 주입
>     - `getBean(~~~~~.class)` 와 동일하다고 볼 수 있다.

---

- 컴포넌트 스캔의 탐색 위치와 기본 스캔 대상

> 📌 `basePackages` 를 지정하지 않으면 @ComponentScan 이 붙은 설정 정보 클래스의 패키지가 스캔의 시작 위치가 된다.
> 권장 → 패키지 위치를 별도로 지정하지 않고 설정 정보 클래스의 위치를 프로젝트 루트 패키지에 두는 것.
> 스프링 부트의 디폴트 컴포넌트 스캔 방식도 이와 같다.
>

![image](/assets/images/47a34182df484bbc87393bb7b21a1558.png)

> ❓ 어노테이션에 따른 스프링의 별도 기능
>
> - `@Controller` : 스프링 MVC 컨트롤러로 인식
>
> - `@Service` : 는 특별한 처리를 하지 않는다. 대신 개발자들이 핵심 비즈니스 로직이 여기에 있겠구나 라고 비즈니스 계층을 인식하는데 도움이 된다.
>
> - `@Repository` : 스프링 데이터 접근 계층으로 인식하고, 데이터 계층의 예외를 스프링 예외로 변환해준다.
>
> - `@Configuration` : 스프링 설정 정보로 인식하고, 스프링 빈이 싱글톤을 유지하도록 추가 처리를 한다.

#### - 필터

{% raw %}
```java
		@Configuration
    @ComponentScan(
//            includeFilters = @Filter(type = FilterType.ANNOTATION, classes = MyExcludeComponent.class),
//            excludeFilters = @Filter(type = FilterType.ANNOTATION, classes = MyExcludeComponent.class)
            //type = FilterType.ANNOTATION -> 기본값
            includeFilters = @Filter(classes = MyExcludeComponent.class),
            excludeFilters = @Filter(classes = MyExcludeComponent.class)
    )
```
{% endraw %}

> ❓ FilterType 옵션
>
> - ANNOTATION: 기본값, 애노테이션을 인식해서 동작한다.
>     - ex) org.example.SomeAnnotation
>
> - ASSIGNABLE_TYPE: 지정한 타입과 자식 타입을 인식해서 동작한다.
>     - ex) org.example.SomeClass
>
> - ASPECTJ: AspectJ 패턴 사용
>     - ex) org.example.._Service+_
>
> - _REGEX: 정규 표현식_
>     - _ex) org\.example\.Default._
>
> - CUSTOM: TypeFilter 이라는 인터페이스를 구현해서 처리
>     - ex) org.example.MyTypeFilter

#### - 중복 등록 및 충돌

1. 자동 빈 등록에서의 중복 이름 충돌

> 📌 컴포넌트 스캔에 의해 자동으로 스프링 빈이 등록되는데, 그 이름이 같은 경우 스프링은 오류를 발생시킨다.
> ConflictingBeanDefinitionException 예외 발생

1. 자동 빈 등록과 수동 빈 등록의 이름 충돌

> 📌 이 경우 수동 빈 등록이 우선권을 가진다.
> (수동 빈이 자동 빈을 오버라이딩 해버린다.)

{% raw %}
```java
Overriding bean definition for bean '빈 이름' with a different definition: replacing ,,,,,,
```
{% endraw %}

> _→ 의도적으로 수동 빈이 오버라이딩 하도록 설정하지 않은 경우가 많기 때문에 최근의 스프링 부트는 수동 - 자동 충돌 또한 오류가 날 수 있도록 기본 값을 바꾸었다._

> 📌 오류 : Consider renaming one of the beans or enabling overriding by setting spring.main.allow-bean-definition-overriding=true
> → 부트의 해당 설정 기본값은 false로 되어 있다.
> 이 설정을 변경하려면 [application.properties](http://application.properties) 등 기본 application 설정 파일에서 해당 값을 true로 바꿔주면 된다.

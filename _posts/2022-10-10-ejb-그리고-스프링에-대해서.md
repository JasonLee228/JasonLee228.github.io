#### 🕐 스프링의 탄생 배경

![image](/assets/images/2e414ba498f44c7683363e73a84b3467.png)

- 기존에 스프링 전에는 **EJB** 라는 기술을 사용

> _EJB(Enterprise Java Beans) : 기업환경의 시스템을 구현하기 위한 서버 측 컴포넌트 모델. 일반적으로 __**업무 로직을 가지고 있는 서버 어플리케이션**__을 EJB라고 한다._

> ⚠️ ORM(Object Relational Mapping), 트랜잭션까지도 지원할 정도로 이론적으로는 괜찮은 기술,,?
>
> <details markdown="1"><summary>ORM이란</summary>
>
>
>
> </details>
>
> - EJB 엔티티 빈 기술 사용
>
> - Entity Bean : 데이터베이스의 데이터를 관리하는 객체
>     - DB 관련 쿼리는 자동으로 만들어지고 개발자는 고급 업무 처리에 집중할 수 있다.
>
> - 한때 기업 애플리케이션의 중심이었던 EJB는 단점이 너무 극명확함
>
> - 비싸고,,느리고
>
> - 어려움, 너무 EJB에 의존적 → **POJO(plan old java object) :** 기존에 옛 자바 오브젝트 기술로 돌아가자는 얘기가 나올 정도.
>
> - EJB는 또한 객체지향적이지 않으며 특정 환경 및 기술에 종속적

#### 🕒스프링의 역사

- 현재 자바 시장에서는** 스프링을 알려면 JPA도 알아야 할 정도**로 둘 다 중요함. 

- 2002년, 로드 존슨은 EJB의 문제점을 지적하면서, 자신이 개발한 새로운 프레임워크의 내용을 책으로 출간.
    - EJB가 없이도 충분히 개발할 수 있음을 보이기 위해 30,000 라인 이상의 예제 코드를 선보임 → 안정성 검증

    - 예제에 스프링의 핵심인 BeanFactory, ApplicationContext, DI, IoC 등의 기술 개념이 포함되어 있음

    - 사람들은 이 예제를 보고 그대로 프로젝트에 사용(?)

> ✅ 책의 출간 이후 유겐 힐러(Juergen Hoeller), 얀 카로프(yann Caroff) 는 로드 존슨에게 해당 **책 내용의 오픈소스 프로젝트**를 제안
>
> - → 전통적인 EJB(J2EE) 라는 겨울을 넘어 ‘새로운 시작’이라는 뜻으로
>     - _**‘스프링’**_의 탄생

#### 🕕스프링의 핵심 생태계

![image](/assets/images/21a556aca238479aa9c40047a8ec61a9.png)

#### 🕖 Spring / Spring Boot

- 스프링 프레임워크 : 스프링 DI, AOP, 데이터베이스 및 웹 접근 기술, 기타 등등 핵심 기술 포함된 필수 프로젝트

- 스프링 부트 : 스프링을 **편리하게 **사용할 수 있도록, 최근에는 그냥 기본!
    - Tomcat 같은 **웹 서버를 내장**, 별도 웹서버 설치 안해도 됨

    - → 단독 실행 가능한 Spring Application을 쉽게 생성할 수 있게 됨

    - 기존 스프링의 단점이었던 어려운 설정 → 관례에 의한 간결한 설정 

  > ⚠️ * 스프링 부트는 스프링 프레임워크와 별도 아님! 
  >
  > [spring.io](http://spring.io) 의 스프링 부트 설명에 다음과 같이 나와있다.
  >
  > > Spring Boot makes it easy to create stand-alone, production-grade Spring based Applications that you can "just run".  
  > > → 실행 가능한 독립된 스프링 애플리케이션을 쉽게 만들 수 있게 해준다.
  >
  > 스프링을 편리하게 사용할 수 있도록 해주는 것일 뿐
  >
  > - 스프링이 없다면 스프링 부트도 존재할 수 없다.

- 나머지 스프링 프로젝트들 - 스프링 데이터, 세션, 시큐리티 … 굉장히 많은 프로젝트

#### 🕣 ‘스프링’ 이라 함은?

> ⚠️ 스프링을 의미하는 말들
>
> 1. 스프링 DI 컨테이너 기술
>
> 1. Spring Framework
>
> 1. 스프링 부트, 스프링 프레임워크를 포함한 스프링 생태계 일체

#### 🕦 스프링이 만들어진 이유, 스프링의 핵심 개념

핵심 개념(왜 만들었는가, 이 기술의 핵심 컨셉은?)

- Spring → JAVA 기반 → 자바 언어의 가장 큰 특징 : **객체 지향 언어**

- 스프링은 객체 지향 언어의 강력한 특징을 살려내는 프레임워크
  → 스프링은 **좋은 객체 지향 애플리케이션**을 개발할 수 있게 도와주는 프레임워크

> ⚠️ 기존의 EJB 컨테이너를 사용한 애플리케이션 개발은 EJB에 너무 종속적
>
> - → 자바 객체 지향 등의 특징과 장점을 모두 잃게 됨
>
> - POJO 가 언급되게 된 이유. 기존의 객체 지향으로 돌아가자!
>
> - 객체 지향을 **‘잘’ 할 수 있도록** 도와주는 스프링은 EJB의 단점을 커버하기에 충분
